# Contributing

Thanks for helping keep this list accurate and useful.

## What belongs here

- Tools whose **primary job** is tracking **web page changes**, **price or availability shifts**, or **structured data drift** on public pages — or self-hosted / API building blocks clearly used for that purpose.
- **Official links** only — vendor homepage or primary GitHub repository, not affiliate URLs.
- **Correct category** — pick SaaS, self-hosted, CLI, API-based, or AI-powered; if it fits two, choose the most common deployment path and mention the other in the description.

## What does not belong

- Pure **uptime ping** products with no meaningful page-diff or content tracking story (unless you explain the keyword/HTML monitoring angle in one neutral line).
- Affiliate or referral links.
- Dead products or abandoned repos (open an issue first for historical entries).

## Pull requests

1. **One tool per PR** when possible; small link fixes can bundle.
2. Add the entry in **alphabetical order** within the **correct section** of `README.md`.
3. Use the same bullet format: `[Name](url) — one neutral sentence (note free tier / self-host / paid where helpful).`
4. If you are **affiliated** with the product, disclose it in the PR.
5. Mention **what you verified** (site still live, category still correct) in the PR body.
6. **Do not add new top-level categories** without an issue first.

## What we skip

- Hype or superlatives (“best,” “#1”) in descriptions.
- Tools that only violate sites’ terms of service by default — we list capabilities, not encouragement to scrape behind logins without permission.
